# Wi-Fi Based Human Activity Recognition and Real-Time Tracking System

AI-powered activity recognition from Wi-Fi Channel State Information
(CSI) — no cameras, no wearables. A real, trained ML pipeline classifies
activity from real Wi-Fi CSI data, served through a FastAPI backend and
visualized on a live React dashboard.

**Read `docs/dataset.md` and `docs/ml-methodology.md` first** — they
explain exactly what's real vs. demo/simulated in this project, and
report actual measured accuracy (not invented numbers).

## What This Is (and Isn't)

- **Real dataset**: genuine Wi-Fi CSI captures (64 complex subcarriers/
  packet) from a public research repository — see `docs/dataset.md`.
- **Real ML**: Random Forest, SVM, CNN, and LSTM trained and compared on
  a held-out test split; best model (CNN, ~97.9% test accuracy on this
  dataset) auto-selected by F1-score. No hardcoded predictions anywhere.
- **DEMO MODE**: replays real held-out CSI windows through the real
  trained model when no hardware is connected — clearly labeled in the
  UI, never presented as a live capture.
- **Instant Action Trigger**: dashboard buttons that pick a real
  held-out window truly labeled as the requested activity and run it
  through the real model — the result shown is whatever the model
  actually predicts, not forced to match the button pressed.
- **CSI Visualization**: waveform, FFT spectrum, and waterfall panels
  are computed from real fetched CSI samples, not decorative animation.
- **Radar / Room View**: humanoid icons at illustrative relative
  positions — explicitly not a claim of real localization or pose
  estimation (no skeleton is inferred from the signal).
- **Not included**: "running" and "gesturing" classes are not in the
  public dataset used, so they are not claimed as supported — see
  `docs/dataset.md` for why and how to add them with real data later.
  Likewise, heart rate / breathing rate / 3D skeleton tracking are
  real but much more advanced research topics this project does not
  attempt — nothing in this dashboard fabricates those numbers.
- **Not a medical device**: this is a final-year academic project, not a
  certified fall-detection product.

## Quick Start (local, no Docker)

### 1. Install & train the ML pipeline
```bash
cd ml
pip install -r ../backend/requirements.txt
python preprocessing.py   # builds dataset/processed/*.npy from raw CSI
python train.py           # trains & compares RF/SVM/CNN/LSTM, saves best model
```
This reproduces `models/evaluation_report.json` and the saved model
artifacts (already included in this delivery, so this step is optional
unless you want to retrain or add data).

### 2. Run the backend
```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
Defaults to a local SQLite file (`wifi_har.db`). To use PostgreSQL
instead, set `DATABASE_URL` (see Environment Variables below).

### 3. Run the frontend
```bash
cd frontend
npm install
npm run dev
```
Open `http://localhost:5173`. The Vite dev server proxies `/api` and
`/ws` to `http://localhost:8000`.

### 4. Start demo mode
In the dashboard's **Settings** tab, choose "Demo" and click
**Start Monitoring** — or via curl:
```bash
curl -X POST http://localhost:8000/api/monitoring/start \
  -H "Content-Type: application/json" \
  -d '{"mode":"demo","interval_seconds":1.5}'
```
Watch Live Monitoring, Timeline, and Alerts update in real time.

## Quick Start (Docker)

```bash
docker-compose up --build
```
- Backend: http://localhost:8000
- Frontend: http://localhost:5173
- Postgres: localhost:5432 (user `wifi_user`, db `wifi_har`)

## Environment Variables

| Variable | Default | Purpose |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./wifi_har.db` | SQLAlchemy DSN. Set to `postgresql://wifi_user:wifi_pass@postgres:5432/wifi_har` for Postgres (docker-compose sets this automatically). |
| `VITE_API_URL` | `` (same-origin, proxied) | Set on the frontend container to point at a non-default backend URL. |

## Demo Mode vs. Live Mode

- **Demo mode** (default): the backend replays real held-out CSI windows
  from the test set through the actual trained model — see
  `backend/app/services/simulation.py`. This is not random-label
  generation; the model genuinely classifies real signal data, just not
  data arriving from live hardware.
- **Live mode**: intended for a real CSI capture device posting windows
  to `POST /api/predict`. See `docs/future-scope.md` for the hardware
  integration path.

## Known Limitations

- Public dataset used has no "running"/"gesturing" samples (see
  `docs/dataset.md`) — not claimed as supported.
- Person Tracking room view shows illustrative relative position, not
  centimeter-level localization.
- Dataset size (744 windows) is modest; treat accuracy figures as
  "measured on this dataset," not a generalization guarantee — see
  `docs/ml-methodology.md`.
- No authentication layer on the API — add one before any real
  multi-tenant deployment.
